# Evidence Identity Model V1.1 — #014-R1

`evidence_id` identifies one immutable Evidence event. `canonical_id` is that event's canonical identity (equal to evidence_id for canonical events, NULL for raw acquisition). `raw_reference_id` identifies the byte archive, never the canonical event. The final archive URI component retains its historical API name `ArchiveIdentity.evidence_id`, but represents the raw reference only.

New acquisition: `ArchiveWriter.write(identity=ArchiveIdentity(run, task, request, "abc123"), evidence_id="RAW-abc123", ...)`. Initial canonical event: `{evidence_id:"EV-00001", canonical_id:"EV-00001", raw_reference_id:"abc123", supersedes_evidence_id:null}`. Upgrades use a new event ID and supersede the previous canonical event, never the raw ID.

Normalize against the exact source bytes; build the canonical record; append normalized content; call `append_evidence(record)`. Reader `evidence(uri, canonical_id)` loads the immutable canonical sidecar and independently checks raw context, raw hash, normalized hash, rules, validation and predecessor. `verify_record` requires the exact stored canonical event. No reader infers canonical identity from a raw URI.

Legacy V1 raw sidecars without `durability_level` are classified as `UNVERIFIED` and rejected under the approved #014-R2 contract (`ARCHIVE_DURABILITY_UNVERIFIED`); they cannot be read as verified archives or enter `ARCHIVED`. There is no rewrite, inferred durability, migration or backfill. Records lacking the identity extension fields may follow the original raw-record checks only when their sidecar already carries a valid explicit `DIRECTORY_SYNC` or `FILE_SYNC_ONLY` level; they are not relabeled as canonical V1.1 records. Existing archive/provider callers can continue acquiring new raw data through the old API; new archive acquisitions always populate raw_reference_id and explicit durability; explicit evidence_id lets callers also separate the raw acquisition event from its URI. Builders recognize legacy initial raw supersedes links at the V1.1 boundary and emit NULL for initial canonical events. The SQLite extension lives in the existing Evidence calculation JSON, with no schema/migration changes. DB projections verify the identity extension against the archive before reporting VERIFIED.

All source enums, fail-closed integrity checks and evidence confirmation semantics remain unchanged. The new sidecar is append-only and create-if-absent, with the same quota, size and sensitive-field gates. As approved in #014-R2, durability now follows the explicit platform contract in [Evidence Archive](frozen/EVIDENCE_ARCHIVE_SIDECAR_V1.0.md): Windows defaults to `FILE_SYNC_ONLY`, Linux defaults to `DIRECTORY_SYNC`, and canonical sidecars record their own durability level. No Provider business logic or model-generated missing facts is added.

Read-only Evidence projections expose `archive_durability_levels` for each verified relevant stage (`raw`, `normalized`, `canonical_evidence`; `analysis_binding` in analysis context) and `durability_level` as their weakest level. Analysis projections also expose the weakest level across input evidence and used evidence bindings. Unverified, unsupported or corrupt projections report `UNVERIFIED`. `integrity_status=VERIFIED` and `REPORT_FULL_TRACE` describe content/binding verification, never a directory durability guarantee: verified content may still be `FILE_SYNC_ONLY`. See the [#014-R2 summary](evidence/014_R2_SUMMARY.md).
